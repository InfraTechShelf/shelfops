# CVAD GUI管理ツール 仕様書（フェーズ4+: セッション操作）

## 0. 位置づけ

フェーズ4（マシン操作）で確立した操作プロトコルの上に、セッション操作を追加する。
本増分のスコープは **セッション一覧・ログオフ・切断** の3つ。

## 1. スコープと除外

| 操作 | cmdlet | 種別 |
|---|---|---|
| セッション一覧 | Get-BrokerSession | 読み取り |
| ログオフ | Stop-BrokerSession | 書き込み（**破壊的**） |
| 切断 | Disconnect-BrokerSession | 書き込み（破壊的） |

**シャドウは本増分に含めない。** シャドウはBrokerコマンドレットで完結する
データ操作ではなく、対象セッションのホストマシンへリモートアシスタンス
（`msra.exe /offerra` 等）を張る対話的な起動であり、ワーカー／Brokerコマンドレットの
モデルに乗らない。実装するなら、管理者のデスクトップ上で外部プロセスを起動する
別経路が要る。次段の課題とする。

## 2. 実装

フェーズ4の操作プロトコル（`{op, site, params}`）をそのまま使う。追加した op:

- `listSessions` … params `{ deliveryGroup, userName, maxCount }`。結果は
  `BrokerOperationResult.Sessions`。
- `logoffSession` / `disconnectSession` … params `{ uid }`。結果は `Message`。

### 対象セッションの特定

ログオフ・切断は、**必ず Uid で1件取得してから `-InputObject` で渡す**。
名前ベースの指定で取り違えるのを避け、対象を一意に確定させるため。

```
$s = Get-BrokerSession -AdminAddress <ddc> -Uid <uid>
if ($s) { Stop-BrokerSession -AdminAddress <ddc> -InputObject $s }  # または Disconnect-BrokerSession
```

セッションが見つからない（既に終了した）場合は、その旨のエラーを返す。

## 3. 破壊的操作の確認

ログオフ・切断はエンドユーザーのセッションを止める。**実行前に必ず確認ダイアログ**を出す。
特にログオフは対象ユーザー・マシンを明示し「保存されていない作業は失われます」と強く警告する。
成否にかかわらず**監査記録としてログに残す**（誰が・どのアカウントで・どのセッションを）。

## 4. GUI

メイン画面に「セッション一覧」ボタンを追加。選択サイトのセッション一覧ウィンドウを開く。
ユーザー名・デリバリーグループで絞り込み可。行を選んで「切断」「ログオフ」。
操作後は一覧を自動更新する（対象セッションは消える／状態が変わる）。

別資格情報サイトでは、ウィンドウを開いている間だけ資格情報を保持
（初回1回入力・閉じたら破棄・ディスクに書かない）。マシン一覧と同じ方針。

## 5. 開発端末での検証（2026-08-11）

SDKが無いので操作はSDK不在で失敗するが、プロトコル・ディスパッチ・GUIは検証済み:
- セッション一覧・ログオフ・切断がワーカー経由で通る
  （統合認証=常駐PID一定 / 別資格情報=毎回別PID・指定アカウント記録）。
- 操作ログにセッション用ラベルとワーカーPIDが出る。
- SessionsWindowの生成、接続テスト・マシン操作・常駐・使い捨ての回帰、GUI起動。
