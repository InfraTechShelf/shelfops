# フェーズ5: ライセンス情報の表示とデリバリーグループの構成管理

作成: 2026-09-21。フェーズ4までの運用操作（マシン・セッション）に続き、
**サイトの構成情報**を扱う段階に入る。5つの要望を、依存関係と危険度に沿って4段階に分ける。

| 要望 | 内容 | 段階 | 性質 |
|---|---|---|---|
| 1 | 接続テストでライセンスサーバー情報を表示 | 0.8 | 読み取り |
| 2 | デリバリーグループ一覧 | 0.8 | 読み取り |
| 3 | DGの全パラメーターを採取・表示・ファイル保存 | 0.9 | 読み取り |
| 4 | 保存ファイルからDGへ再設定（復元） | 1.0 | **書き込み** |
| 5 | DGの全パラメーターをGUIで設定 | 1.0以降 | **書き込み** |

**差別化の核は 3〜5 にある。** Citrix Studio には「デリバリーグループの設定を保存する」「保存時点と
比較する」「変更前に差分を確認する」機能が無い。ShelfOps はこれを持つ。

## 決定事項

- 3項の「全パラメーター」は **DG本体＋関連オブジェクト**（アクセスポリシー・権利付与ルール・
  公開アプリ・電源スキーム・再起動スケジュール・タグ）とする。DG本体だけでは
  Studio で見える「デリバリーグループの設定」の半分に満たない
- 4項の復元は、第1弾では **同一サイトの既存DGへの設定戻し**に限定する。
  ただし**将来の別サイト移行を見据え、保存形式は最初から移行可能な設計**にする（§4.2）
- 5項は Studio 風のフォームではなく、**プロパティグリッド＋差分適用**とする。4項と同じ
  エンジンの上に載せ、「適用前に何が変わるか必ず見える」という Studio に無い価値を付ける

## 1. ライセンス情報の表示（0.8）

### 1.1 取得元

接続テストは既に `Get-BrokerSite` と `Get-BrokerController` を呼んでいる
（[CitrixConnectionService](../src/CitrixAdminTool.Core/Connection/CitrixConnectionService.cs)）。
**新しいコマンドレットは不要**で、取り出すプロパティを増やすだけ。

| 表示項目 | プロパティ | 取得元 |
|---|---|---|
| ライセンスサーバー | `LicenseServerName` / `LicenseServerPort` | Get-BrokerSite |
| 製品 | `ProductCode`（XDT = Virtual Apps and Desktops / MPS = Virtual Apps） | Get-BrokerSite |
| エディション | `ProductEdition`（PLT / ENT / ADV / STD …） | Get-BrokerSite |
| ライセンスモデル | `LicensingModel`（UserDevice / Concurrent） | Get-BrokerSite |
| 猶予期間 | `LicensingGracePeriodActive` / `LicensingGraceHoursLeft` | Get-BrokerSite |
| **接続状況（DDCごと）** | `LicensingServerState`（OK / NotConnected / LicenseExpired / Failed …） | Get-BrokerController |
| 猶予状態（DDCごと） | `LicensingGraceState`（NotActive / InSupplementalGracePeriod / …） | Get-BrokerController |

「接続状況」は **DDC ごとの値**である点が重要。サイト全体で1つではなく、
「DDC-01 は OK だが DDC-02 だけライセンスサーバーに繋がっていない」が起きる。
コントローラ単位で並べて表示する。

### 1.2 表示

- 接続結果テキスト（右ペイン）に「ライセンス」の節を追加。ログにも同じ内容を残す
- サイト一覧の状態欄（`StatusDetail`）に、**猶予期間中なら警告**を出す
  （`LicensingGracePeriodActive == true` は「ライセンスサーバーと通信できていない」ことを意味し、
  猶予が切れると新規セッションが拒否される。接続テストの成否より先に気づくべき状態）
- 値の英語表記（`UserDevice` 等）はそのまま出す。SDKの値であり、訳すと調査時に突き合わせにくい

### 1.3 注意

- プロパティ名は CVAD のバージョンで揺れる可能性がある。既存の方針どおり、無ければ空欄にして
  落とさない（`GetProp` は null を返す）
- `Get-BrokerController` は既にバージョン取得で呼んでいるため、追加の往復は発生しない

## 2. デリバリーグループ一覧（0.8）

### 2.1 取得

`Get-BrokerDesktopGroup -AdminAddress <ddc> -MaxRecordCount <int.MaxValue>`（読み取り専用）。
マシン一覧・セッション一覧と同じ構造で実装する:

- Core: `BrokerDesktopGroup` モデル、`ListDesktopGroups` 操作、ワーカープロトコルの op 追加
- WPF: `DesktopGroupsViewModel` / `DesktopGroupsWindow`。絞り込み・書き出し（CSV／クリップボード）・
  両言語は既存部品を流用

### 2.2 列

| 列 | プロパティ | 備考 |
|---|---|---|
| 名前 | `Name` | |
| 有効 | `Enabled` | |
| メンテ | `InMaintenanceMode` | マシン一覧と同じ ON/OFF 表記・色 |
| 種別 | `DesktopKind`（Private / Shared） | |
| 配信 | `DeliveryType`（DesktopsOnly / AppsOnly / DesktopsAndApps） | |
| セッション | `SessionSupport`（Single / Multi） | マシン一覧と同じ訳 |
| マシン数 | `TotalDesktops` | |
| 使用中 | `DesktopsInUse` | |
| 未登録 | `DesktopsUnregistered` | 0 でなければ目立たせる（登録漏れの早期発見） |
| セッション数 | `Sessions` | |
| 説明 | `Description` | |

絞り込み: 種別・配信・有効／無効・メンテ・名前の部分一致。

### 2.3 この画面が 3項以降の入口になる

一覧で DG を選び、「設定を保存」「保存ファイルと比較」「復元」をここから起動する。
0.8 では一覧と書き出しのみ。ボタンの置き場所（2段ツールバー）は 0.9 で足す前提でレイアウトする。

## 3. 構成のスナップショット（0.9）

### 3.1 何を採るか

1つのDGについて、以下をまとめて1ファイルにする。

| 要素 | コマンドレット | 補足 |
|---|---|---|
| DG本体 | `Get-BrokerDesktopGroup -Uid` | 約60プロパティ。**すべて保存する**（設定可否は適用側で判定） |
| アクセスポリシー | `Get-BrokerAccessPolicyRule -DesktopGroupUid` | 「ユーザー」画面の接続元条件・許可ユーザー |
| 権利付与（デスクトップ） | `Get-BrokerEntitlementPolicyRule -DesktopGroupUid` | 共有デスクトップの利用者 |
| 権利付与（アプリ） | `Get-BrokerAppEntitlementPolicyRule -DesktopGroupUid` | 公開アプリの利用者 |
| 割り当て（専有） | `Get-BrokerAssignmentPolicyRule -DesktopGroupUid` | 専有デスクトップの割り当て規則 |
| 公開アプリケーション | `Get-BrokerApplication -DesktopGroupUid` | 名前・実行ファイル・引数・表示設定 |
| 電源スキーム | `Get-BrokerPowerTimeScheme -DesktopGroupUid` | 曜日×時間帯のピーク定義とプール容量 |
| 再起動スケジュール | `Get-BrokerRebootScheduleV2 -DesktopGroupUid` | |
| タグ | `Get-BrokerTag -DesktopGroupUid` | |

これらは **すべて Citrix.Broker.Admin.V2 に含まれる**。新しい SDK モジュールは不要。
1つの Runspace 内でまとめて取得する（既存の一括操作と同じく、SDKロードは1回）。

### 3.2 ファイル形式（移行を見据えた設計） ★

将来の別サイト移行で問題になるのは、**Uid と SID がサイト固有**であること。
保存時点でこれを織り込んでおけば、後から適用エンジン側だけを拡張すればよい。

```
{
  "format": "shelfops-desktopgroup",
  "formatVersion": 1,
  "capturedAt": "2026-09-21T10:00:00+09:00",
  "capturedBy": "CORP\\admin01",
  "site": { "name": "...", "ddc": "ddc01...", "version": "7.2507" },
  "desktopGroup": {
    "name": "...",                 ← 対応付けの主キー。Uid は参考情報
    "uid": 12,
    "properties": { ...全プロパティ... }
  },
  "accessPolicyRules": [ { "name": "...", "properties": { ... } } ],
  "entitlementPolicyRules": [ ... ],
  "appEntitlementPolicyRules": [ ... ],
  "assignmentPolicyRules": [ ... ],
  "applications": [ ... ],
  "powerTimeSchemes": [ ... ],
  "rebootSchedules": [ ... ],
  "tags": [ "..." ]
}
```

設計原則:

- **対応付けは Uid ではなく名前で行う。** DG・ルール・アプリ・スキームはいずれも名前を持つ。
  Uid は保存するが参考情報であり、適用時の照合には使わない
- **ユーザー／グループは SID と名前の両方を保存する。** 同一サイトでは SID で照合し、
  別サイト（別ドメイン）では名前で再解決する道を残す
- **プロパティは取得したまま全部保存する。** 「設定できるか」を保存側で判断すると、
  CVAD のバージョン差で取りこぼす。判断は適用側に寄せる（§4.3）
- 既存の `JsonWriter` / `JsonParser` で読み書きする。外部依存は増やさない

### 3.3 表示と保存

- 採取結果はツリー（要素 → プロパティ）で表示。検索欄で絞れるようにする（60項目は目で探せない）
- 「ファイルに保存...」で `ShelfOps_dg_<DG名>_yyyyMMdd_HHmmss.json`
- **「保存ファイルと比較」を 0.9 で入れる。** 適用はしない、差分を見せるだけ。
  これだけで「先週から何が変わったか」の変更管理に使え、4項の差分表示部分の先行実装にもなる

### 3.4 ファイルの取り扱い

保存ファイルにはユーザー／グループ名と SID、マシン名、アプリの実行パスが含まれる。
資格情報は含まない。ログと同じ扱い（共有時は内容を確認する）で、クイックスタートに明記する。

## 4. 差分適用エンジンと復元（1.0）

### 4.1 流れ

```
望ましい状態（ファイル or 編集結果）
        ↓
現在の状態を取得（§3.1 と同じ経路）
        ↓
差分を計算 ──→ 差分表示（変更なし／変更あり／適用不可／ファイルに無い）
        ↓
確認（件数と内容を明示。既存の書き込み操作と同じ作法）
        ↓
適用（1プロパティ・1ルールごとに実行、途中で失敗しても止めない）
        ↓
対象ごとの結果（既存の「内訳」ウィンドウを流用）＋ログ
```

**差分表示なしに適用する経路は作らない。** 復元は本ツールで最も影響範囲の広い書き込みになる。

### 4.2 第1弾の対象範囲

- 同一サイトの、**既に存在する**同名DGへの適用のみ
- DG の新規作成（`New-BrokerDesktopGroup`）は行わない。DGが無ければエラーで止める
- ファイルの `site.name` と接続先が一致しなければ警告を出す（別サイトへの適用は明示的な確認を要求）

### 4.3 設定可能プロパティの判定 ★

`Get-BrokerDesktopGroup` が返す約60のうち、`Set-BrokerDesktopGroup` で書けるのは一部。
`Uid`・`TotalDesktops`・`Sessions` などは計算値、`DesktopKind`・`SessionSupport` は作成後変更不可。

**ホワイトリストを手書きしない。** 実行時に `Get-Command Set-BrokerDesktopGroup` の
パラメータ一覧を読み、**その SDK が受け付けるパラメータだけを設定可能とみなす**。
これにより CVAD のバージョン差（パラメータの追加・廃止）に自動で追従する。
差分表示では、ファイルにあるが設定できないプロパティを「適用不可（読み取り専用）」として
明示し、黙って捨てない。

### 4.4 関連オブジェクトの適用規則

| 状況 | 動作 |
|---|---|
| 名前が一致するルールがある | `Set-*` で差分のあるプロパティだけ更新 |
| ファイルにあり、現在に無い | `New-*` で作成 |
| 現在にあり、ファイルに無い | **既定では削除しない。** 差分表示に「ファイルに無い」として出し、削除はチェックボックスで明示的に選んだ場合のみ |

削除を既定で行わない理由: 保存後に正当に追加されたルールを、古いファイルの適用で消す事故を防ぐ。
「保存時点に完全に戻す」より「保存時点の内容を確実に反映する」を優先する。

### 4.5 適用順序

依存関係のある順に適用する: DG本体 → タグ → 電源スキーム → 再起動スケジュール →
アクセスポリシー → 権利付与ルール → 公開アプリ。
途中で失敗しても残りを試み、結果は対象ごとに記録する（既存の一括操作と同じ）。

### 4.6 権限

読み取り（0.8 / 0.9）は Read Only Administrator / Help Desk で動く。
適用（1.0）には Delivery Group Administrator 以上が要る。権限不足は対象ごとの失敗として
「アクセスが拒否されました」を表示し、途中で止めない。

### 4.7 将来の別サイト移行のために残す道

第1弾では実装しないが、§3.2 の形式のおかげで、以下を足すだけで移行に進める:

- DG が無い場合の `New-BrokerDesktopGroup`（カタログの対応付けが必要）
- ユーザー／グループを SID ではなく名前で再解決する経路（`Get-BrokerUser` / AD 参照）
- 公開アプリの実行パスの差し替え（サイト間でインストール先が違う場合）

## 5. プロパティグリッドによる編集（1.0以降）

- 現在の設定（§3.1）を読み込み、**キー／値の一覧**として表示。型に応じた編集
  （真偽値はチェック、列挙型はプルダウン、数値は範囲、文字列はテキスト）
- 設定不可のプロパティ（§4.3）は編集不可として灰色表示。理由もツールチップで示す
- 「適用」を押すと §4 の差分適用エンジンに渡る。**編集結果をファイルとして保存**することもできる
  （編集＝望ましい状態の作成、と位置づける）
- ユーザー／グループの選択（AD参照）は第1弾では扱わない。ルールの利用者変更は
  保存ファイルを編集して適用する経路で代替する

Studio 風のフォームは作らない。60項目分の入力欄と検証を手作りする工数に対して、
得られるのは「Studio と同じことができる」だけであり、差別化にならない。

## 6. 実装順と版

| 版 | 内容 | 危険度 |
|---|---|---|
| 0.8 | §1 ライセンス表示、§2 DG一覧 | 読み取りのみ。既存パターンの延長 |
| 0.9 | §3 スナップショット採取・保存・**保存ファイルとの比較**（表示のみ） | 読み取りのみ。差分表示の先行実装 |
| 1.0 | §4 差分適用による復元（同一サイト・既存DG） | 書き込み。差分プレビュー必須 |
| 以降 | §5 プロパティグリッド編集、§4.7 別サイト移行 | |

0.9 の時点で「保存して比較する」が成立する。変更管理・監査の用途で単体でも価値があり、
1.0 の適用エンジンに進む前に、差分計算の正しさを**書き込みなしで**検証できる。

## 7. 未確定・要検討

- 電源スキーム（`PowerTimeScheme`）の曜日×時間帯データは配列で持つ。差分表示をどう見せるか
  （時間帯グリッドを描くか、変更の有無だけ示すか）は 0.9 で判断する
- 公開アプリの**アイコン**（`IconUid`）はサイト固有。保存に含めるか、名前で再解決するか未定
- 保存ファイルの暗号化は行わない（資格情報を含まないため）。ただし共有時の注意は文書化する
- `Get-BrokerRebootScheduleV2` は CVAD 7.x 後期からの名前。古いサイトでは V1 の可能性があり、
  無ければ空で保存する
