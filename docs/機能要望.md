## R-1. マシン一覧に電源操作を追加（2026-09-23 受領 / **0.9 で実装済み**）

**実装時の記録**: 0.9 の主機能（スナップショット採取・比較）と触るファイルが一切重ならないことを
確認したうえで同じ版に入れた。Core 層の変更はゼロで、追加は `MachinesViewModel` と
`MachinesWindow` のみ。文言も既存の `Power_*` キーをほぼそのまま再利用し、
マシン一覧固有の3キー（メニューのツールチップ・影響範囲の文面）だけを足した。

マシン一覧のウィンドウからも、マシンのシャットダウン・再起動などを実行できるようにする。
**提供する操作はセッション一覧に実装済みのものと同じ**で構わない、との方針。

### 背景

0.7.0 でセッション一覧に電源操作を入れたが、**マシンを起点に操作したい場面がある**。

- セッションが無いマシン（未登録・起動していない・誰もログオンしていない）は
  セッション一覧に現れないため、現状ではツールから電源操作ができない
- 「未登録のマシンを再起動して登録し直させる」は VDA トラブルの定番の対処で、
  デリバリーグループ一覧（0.8）で未登録を見つけたあとの自然な次の操作になる
- メンテナンスモードに入れてから再起動する、という流れはマシン一覧内で完結する方が速い

### 実装範囲

提供する操作はセッション一覧と同じ4つ。

| 操作 | SDK | 備考 |
|---|---|---|
| シャットダウン | `New-BrokerHostingPowerAction -Action Shutdown` | OSに正常終了を要求。応答しないマシンには効かない |
| 再起動 | 同 `-Action Restart` | 同上 |
| 強制電源オフ | 同 `-Action TurnOff` | OSに終了処理をさせない |
| 強制リセット | 同 `-Action Reset` | 同上。応答しないVDIの復旧用 |

**Core 側の追加は不要。** `BrokerOperationService.PowerActionBulk(site, machineNames, action)` は
既にマシン名のリストを受け取る形で、セッション一覧はそこへ「セッション → マシン名」を
変換して渡しているだけ。マシン一覧からは変換せずそのまま呼べる。
ワーカープロトコルの `powerActionBulk` もそのまま使える。

変更が要るのは WPF 側のみ:

- `MachinesViewModel` に `PowerActionAsync(IList<BrokerMachine>, BrokerPowerAction)` を追加
- `MachinesWindow` のツールバーに「電源操作 ▾」メニュー（セッション一覧と同じ並び・同じ色分け）と
  右クリックメニューの項目を追加
- 文言はセッション一覧のものをそのまま再利用できる（`Power_*` キーは操作名・注意文とも
  マシンを対象にした表現になっている）

### 設計上の注意 ★

**確認ダイアログで示す影響範囲の作り方がセッション一覧とは変わる。**

セッション一覧では「選択したセッションは1件だが、そのマシン上には合計5件のセッションがある」と
警告している。これは取得済みのセッション一覧から数えていた。

マシン一覧には**セッションの一覧が無い**。ただし `BrokerMachine.SessionCount`（セッション数）は
取得済みなので、**対象マシンの SessionCount を合計**すれば同じ趣旨の警告が出せる。

- 「3 台のマシンに【再起動】を要求します。これらのマシンでは合計 12 件のセッションが動作しています」
- SessionCount が 0 のマシンだけなら、その旨を出して警告を弱める
  （未登録マシンの再起動など、利用者影響が無いケースで過剰に脅かさない）
- 件数は前回の「更新」時点のスナップショットである旨は、セッション一覧と同様に添える

**電源管理されていないマシンでは失敗する**点も同じ。対象ごとの結果（`Targets`）で理由を返し、
「内訳」ウィンドウで確認できる。マシン一覧には既に `LastOperationResult` と「内訳」ボタンが
あるので、そのまま流用できる。

### 検討事項

- メンテナンスモードの操作ボタンと電源操作メニューが同じツールバー上段に並ぶ。
  ボタン数が増えるため、配置は実装時に確認する（マシン一覧の上段は現在
  更新／メンテON／メンテOFF／Excelへコピー／CSV保存...）
- 「メンテナンスモードON → 再起動」をひとつの操作にまとめるかは**今回は見送る**。
  複合操作は途中失敗時の状態が分かりにくく、対象ごとの結果の表現も複雑になる。
  まず個別の操作として提供し、要望が出てから検討する
