**英語対応の設計上の要点**

- **.resx / サテライトアセンブリは使わない。** 「フォルダをコピーすれば動く」形と
  外部依存ゼロの方針を維持するため、文言はアセンブリ内の辞書で持つ
- **キーごとに日英を並べた1つの表**（`StringTable.cs`）にしている。言語別にファイルを分けると
  片方だけ追記して訳が抜けるため、構造的に訳漏れが起きない形にした。
  未定義キーは画面に `!!キー名!!` と出るので、検証時に必ず気づける
- XAMLは `{loc:T キー}`（`TExtension`）でインデクサへバインドする。
  Source を明示しているため **`DataGridColumn.Header` のようにビジュアルツリー外の要素でも効く**
- 絞り込みの選択肢（`(すべて)` 等）は文言そのものが値になるため、言語切替時は
  **選択位置を覚えて位置で復元**する（並び順は言語で変わらない）
- ログの項目見出しは言語で文字数が変わる。全角を2幅として数えて桁を揃えている
- Coreのモデルには表示用の日本語ラベルを持たせない方針に変更した
  （`SessionSupportLabel` は廃止し、画面側のコンバーターで訳す）

### 実装時に見つかった注意点

- **DDCフェイルオーバーとの相性**: 一括書き込みが全対象失敗した場合、
  従来の実装では次のDDCで再実行され、**同じ書き込みを二度行う**恐れがあった。

- **常駐ワーカーの再送**: 送信後に失敗した場合の再送も、ログオフ等を二重実行しうるため
  やめた。再試行するのは「送る前に接続が壊れていた」場合だけ。

## 1. マシン一覧: カタログでの絞り込み

現在プルダウンがあるのは「デリバリーグループ」のみ。**カタログ**でも絞り込めるようにする。

- 実装は既存のデリバリーグループ絞り込みと同型。取得結果から実在するカタログ名を集めて
  プルダウンにする（`(すべて)` ／必要なら `(未所属)`）。
- `BrokerMachine.CatalogName` は取得済みなので、Core側の変更は不要。
  `MachinesViewModel` に `Catalogs` / `CatalogFilter` を追加し `ApplyFilter` に条件を足すだけ。

## 2. メンテナンスモードの複数選択対応

現在は1台ずつしか切り替えられない。**複数マシンをまとめてON/OFF**できるようにする。

- `DataGrid` の `SelectionMode` を `Extended` にし、選択された全行を対象にする。
- 確認ダイアログは「N台のメンテナンスモードをONにします」と件数を明示。
  対象が少数なら名前を列挙、多数なら件数＋代表例に留める（ダイアログが巨大化しないよう）。
- 実行は1台ずつ `Set-BrokerMachine` を呼ぶループになる。**途中で失敗しても止めず**、
  最後に「成功 N 台 / 失敗 M 台」を集計して返す設計にする
  （権限やマシン状態で一部だけ失敗するケースが現実にあるため）。
- ログには対象一覧と各結果を残す（監査記録）。

### 2.1 結果の内訳を画面で確認できるようにする ★

「成功 8 台 / 失敗 2 台」だけでは**どのマシンが失敗したか分からず対処できない**。
結果表示の横に **「内訳」ボタン**を置き、押すと明細を表示する。

- 明細に出す情報: マシン名 / 成功・失敗 / 失敗理由。
- 失敗した行がすぐ分かるようにする（失敗を上に並べる、色を変える等）。
- 一覧としてコピーできると調査に使いやすい（テキスト選択可、またはコピーボタン）。
- 対象が多い場合に備え、明細はスクロール可能なウィンドウにする。

補足: ログファイルには全件の結果が残る設計なので情報自体は失われないが、
**失敗直後に画面で確認できる**方が実務上はるかに速い。
セッション一覧の一括操作（5項）でも同じ内訳表示を使う。

実装メモ: `BrokerOperationResult` に「対象ごとの結果」を持つリストを追加し
（対象名・成否・エラー文）、一括操作はそこに1件ずつ積む。
GUIはそれを内訳ウィンドウに表示する。単一操作でも同じ構造で扱えるので、
既存の表示・ログ整形もこの構造に寄せる。

## 3. メンテ列の表現改善 ★重要

**現状の問題**: 「メンテ」列がチェックボックスなので、
**行の選択状態**を表すのか**メンテナンスモードのON/OFF**を表すのか紛らわしい。
複数選択に対応すると、この混同はさらに悪化する。

**改善方針**:
- **チェックボックス = 行の選択**（複数選択用）に役割を統一する。
- **メンテナンスモードの状態は「ON」/「OFF」の文字**で表示する。
- さらに**文字色を変える**と判別しやすい（例: ON = 目立つ色／OFF = 目立たない色）。

**背景**: Citrix Studio は「オン」「オフ」のカタカナ表記で、
一覧の中で瞬時に判別しにくい。ShelfOps では**視認性で上回る**ことを狙う。

## 4. メンテナンスモードでの絞り込み（要検討）

メンテON/OFFで絞り込みたい。ただし**プルダウンが増えるとUIがごちゃつく**懸念がある。

検討案:
- トグルボタン（「メンテONのみ」を押している間だけ絞り込む）
- 3状態トグル（すべて → ONのみ → OFFのみ）
- 既存プルダウンに統合するか、フィルタ行を別途設けるか

→ 実装前にUI配置を検討し、判断を仰ぐこと。

## 5. セッション一覧: 複数選択対応

マシン一覧と同様に、**切断・ログオフの対象を複数選択**できるようにする。

- 破壊的操作なので確認ダイアログは特に慎重に。件数を明示し、

- こちらも途中で失敗しても止めず、集計結果を返す。
- **結果の内訳表示（2.1項）を同じ仕組みで使う**。どのセッションが失敗したかを

## 7. 一覧のエクスポート（セッション一覧・マシン一覧）

取得した一覧を**ファイルに書き出せる**ようにする。棚卸し・報告・他部署への連携で、
画面を見ながら手で転記している状況をなくす。CSV は必須。

### 7.1 出力形式

**必須: CSV**

- 文字コードは **UTF-8（BOM付き）**。BOM無しだと Excel で開いたとき日本語が化ける
  （ログ出力 `RunLogWriter` で BOM 付きにしているのと同じ理由）。
- 改行コードは CRLF、区切りはカンマ、RFC 4180 に従ってエスケープする
  （値に `,` `"` 改行 が含まれたら `"` で囲み、内部の `"` は `""` に二重化）。
  クライアント端末名やユーザー名は任意の文字列が入りうるので、素の文字列連結で作らないこと。
- **1行目はヘッダ（列名）**。サイト名・取得時刻・DDC といったメタ情報を先頭行に入れると
  Excel で表として扱えなくなるため、**メタ情報はファイル名側に持たせる**。
  - 既定ファイル名: `ShelfOps_machines_<サイトID>_yyyyMMdd_HHmmss.csv`
    ／ `ShelfOps_sessions_<サイトID>_yyyyMMdd_HHmmss.csv`
- 先頭が `=` `+` `-` `@` で始まる値は Excel が数式として解釈する（CSVインジェクション）。
  ユーザー名・クライアント名は外部由来の文字列なので、**先頭に `'` を付ける等の無害化**を入れる。

**必須: クリップボードへのコピー（TSV） ★実運用の主力**

実務で一番多いのは「一覧を Excel に貼って報告資料にする」という流れで、
ファイルを作って開き直すより **タブ区切りで直接クリップボードへ入れる方が速い**。
整形処理は CSV と区切り文字違いなので、追加コストの割に効果が大きい。

**入口は2つ用意する。役割が違うので両方入れる。**

1. **`Ctrl+C`（DataGrid 標準機能）** — 「選択した数行だけ」を手早くコピーする用。
   WPF の `DataGrid` に `ClipboardCopyMode="IncludeHeader"` を指定するだけで有効になり、
   **自前の実装は不要**。ただし現在は `SelectionMode="Single"` なので1行しか取れない。
   **複数選択（2項・5項）を入れて初めて実用になる**ため、そちらとセットで対応する。
   コピーされるのは画面に出ている列だけ（DNS名・Uid のような非表示項目は含まれない）。

2. **ツールバーの「Excelへコピー」ボタン** — 「絞り込んだ結果を丸ごと」コピーする用。
   選択の有無に関わらず押せる。7.3 の列（非表示項目も含む）を出せるのはこちら。
   ラベルは「コピー」だと何をコピーするのか分からないので、**用途が読み取れる語にする**。

`Ctrl+C` は選択行、ボタンは一覧全体、と役割が分かれるので競合しない。

**実装上の注意（この種のツールでは実際に踏む）★**

- `Clipboard.SetText` は他プロセスがクリップボードを掴んでいると
  `CLIPBRD_E_CANT_OPEN` で例外を投げる。**本ツールは RDP／ICA セッション内の
  管理端末で動かすことが多く、クリップボードリダイレクトが絡んで実際に発生する**。
  リトライ付きの `Clipboard.SetDataObject(text, true, 10, 100)` を使い、
  それでも失敗したらステータスに理由を出す（無言で失敗させない）。
- 値にタブ・改行が混じると列がずれる。**半角空白へ置換**して1セルに収める。
- コピー後は必ず件数をステータスに出す。クリップボードは目に見えないので、
  「コピーできたのか」がフィードバック無しでは分からない。

**任意: JSON**

他ツール連携・スクリプトでの後処理向け。`JsonWriter` が既にあるので依存追加なしで書ける。
実装コストは低いが、**使う人が居るか不明**なので優先度は下げてよい。要望が出てから足す。

**見送り: XLSX（Excel ネイティブ）**

本ツールは**外部ライブラリを持たない方針**（ClosedXML / EPPlus 等）。
xlsx は ZIP + OOXML の手書きになり実装量に見合わない。
「Excel で開ける」要件は CSV とクリップボードコピーで満たせる。

### 7.2 出力範囲

**選択があれば選択行、無ければ表示中（絞り込み後）の全行**を出す。
エクスプローラや Excel と同じ感覚で、モード切替の UI を増やさずに済む。
`Ctrl+C` は常に選択行（DataGrid 標準の挙動）。

どちらを出したかは必ずステータスに出す
（「表示中 120 件をコピーしました」／「選択した 3 件をCSVに保存しました」）。
**絞り込み前の全件が要る場合は、絞り込みを `(すべて)` に戻してから実行する**
という運用にし、「全件出力」の専用UIは作らない。ボタンが増えるほど迷うため。

### 7.3 出力する列

**画面の列 ＋ 画面に出していないが調査に要る項目**を出す。ファイルは横に広くても困らない。

- マシン一覧: マシン名 / **DNS名** / カタログ / デリバリーグループ / 種別 /
  登録 / 電源 / 状態 / セッション数 / メンテナンスモード / **割り当てユーザー（8項）**
- セッション一覧: ユーザー / マシン / デリバリーグループ / 状態 / クライアント /
  開始時刻 / 状態変更時刻 / **Uid**

メンテナンスモードは CSV では `ON` / `OFF`（3項の画面表記と揃える）。
`True` / `False` は Excel で真偽値に変換されて表記が揺れるため使わない。

### 7.4 UI と実装メモ

- ツールバーには **「Excelへコピー」と「CSV保存...」の2つ**を置く。
  末尾の `...` は「押すとダイアログが出る」というWindowsの慣習に従う。
  ツールバーは既に窮屈なので、**操作行とフィルタ行の2段化（末尾「設計上の注意」）を
  先に済ませてから**載せること。
- **同じ2項目を DataGrid の右クリックメニューにも出す**。一覧を見ながら
  そのまま操作できる方が速く、ツールバーまで視線を戻さずに済む。
- 保存先は `Microsoft.Win32.SaveFileDialog`（`PresentationFramework` に含まれるので依存追加なし）。
- 整形は **マシン用・セッション用で共通のヘルパー**に切り出す
  （`Services\TableExporter` 等）。「列定義（見出し＋値の取り出し方）の配列」を渡すと
  CSV文字列／TSV文字列を返す形にすれば、CSV・TSV・将来のJSONで整形処理を再実装せずに済む。
  マシンとセッションの違いは**列定義だけ**に閉じ込める。
- **書き出しは監査記録としてログにも1行残す**（誰がいつ何件持ち出したか）。
  一覧の内容そのものはログに書かない（ログが肥大化するため）。
  クリップボードコピーも「持ち出し」なので同様に記録する。
- 保存先がロックされている／権限が無い場合は、例外を握りつぶさずステータスに理由を出す。

## 8. マシン一覧に「割り当てユーザー」列を追加

静的割り当て（専有）のマシンが**誰に割り当てられているか**を一覧で確認できるようにする。
現在は Citrix Studio を開かないと分からない。

### 8.1 取得元

`Get-BrokerMachine` の **`AssociatedUserNames`**（`DOMAIN\user` 形式）を使う。
表示名が要るなら `AssociatedUserFullNames`、UPN が要るなら `AssociatedUserUPNs` もある。
まずは運用で使う `AssociatedUserNames` のみを取る。

### 8.2 実装上の注意 ★

**この値は配列（`string[]`）で返る。** 既存の `BrokerSdkHelpers.GetProp` は
`value.ToString()` しているため、そのまま使うと **`System.String[]` という文字列が入ってしまう**。
配列を受けて要素を連結する取り出し関数（`GetStringsProp` 等・区切りは `"; "`）を新設すること。

変更が必要な箇所は以下の4つ。**どれか1つでも漏れると画面に出ない**ので併せて直す:

1. `Models\BrokerMachine.cs` — プロパティ追加（`AssociatedUserNames`）
2. `Connection\BrokerOperationService.cs` の `ToMachine` — 上記の配列対応で詰める
3. `Interop\WorkerProtocol.cs` の `MachineToDict` / `MachineFromDict` — **ワーカー↔GUI の受け渡し**。
   ここを忘れると Core では取れているのに GUI では常に空になる
4. `Views\MachinesWindow.xaml` — 列の追加

（GUI とワーカーは同じパッケージで配布するため、プロトコル項目の追加による
バージョン不整合の心配は無い。）

### 8.3 表示

- 列名は「割り当てユーザー」。マシン名・カタログの近くに置く。
- **マルチセッションのマシンでは通常この値は空**（ログオン中のユーザーはセッション一覧側で見る）。
  空欄が並ぶのは正常であり不具合ではない、とヘルプ／ツールチップで補足する。
- 複数人に割り当てられている場合は `; ` 区切りで並べる。長くなるので
  列は `TextTrimming` で省略表示にし、ツールチップで全体を出す。
- 7項のエクスポートにもこの列を含める。

### 8.4 併せて検討

マシン名の部分一致検索（`MachineNameFilter`）の対象に**割り当てユーザー名も含める**と、
「このユーザーの専有マシンはどれか」を1つの検索欄で引ける。
その場合、検索欄のラベルとツールチップを実態に合わせて変更すること
（現在は「マシン名」= マシン名・DNS名 の2つが対象）。

## 9. サイトの複製（コピー）

サイト一覧で選択中のサイトを**複製**できるようにする。
同一サイトを別の認証モードで登録したい、DDC構成が似た検証サイトを足したい、
といった場合に、DDCのFQDNを手で打ち直す必要がなくなる（打ち間違いの防止にもなる）。

### 9.1 動作

- 「追加」「削除」の隣に **「複製」ボタン**を置く（`MainWindow.xaml` のサイト一覧上部）。
- 選択中サイトが無ければ無効（`DeleteSiteCommand` と同じ `CanExecute` 条件）。
- コピー元の **プライマリDDC / 代替DDC / 認証モード** をそのまま引き継ぐ。
- **ID は必ず新しくする**（重複IDは保存時に弾かれる仕様のため）。
  `<元のID>-copy`、既にあれば `-copy2`, `-copy3` … と採番する。
  既存の `MakeUniqueId()` は `site-N` 形式なので、複製用の採番は別に用意する。
- 表示名は `<元の表示名> のコピー`。
- **接続状態（`Status` / `StatusDetail`）は引き継がない**（`Unknown` のまま）。
  複製しただけで接続確認済みに見えるのは誤解を生むため。
- 複製した行は**元の行の直下**に挿入し、それを選択状態にする。
  末尾に足すとサイトが多いときに見失う。
- 追加・削除と同様、**未保存（`IsDirty`）** になる。確定は「保存」。

### 9.2 実装メモ

`SiteViewModel` に複製用のメソッドを持たせるのが素直
（`ToModel()` → `FromModel()` を経由すれば、代替DDCの複数行テキストの
パース／再構成も既存ロジックで済み、コピー漏れが起きない）。
`Sites.Insert(index + 1, copy)` で挿入すれば、既存の `CollectionChanged` フックにより
`IsDirty` とコマンド状態は自動で更新される。

## 実装順の目安

1. **9項（サイトの複製）** — 他とほぼ独立し、影響範囲がサイト一覧に閉じる。先に片付けられる。
2. **3項（メンテ列の表現改善）** — 2項の前提。混同を解消してから複数選択に進む。
3. **2項・5項（複数選択）** — マシンとセッションで同じ設計を使う。
4. **8項（割り当てユーザー列）** — Core〜ワーカー〜GUI を貫通する変更。7項より先に入れて、
   エクスポートの列定義を一度で確定させる。
5. **1項・6項（絞り込み追加）** — 既存の仕組みの拡張で低リスク。
6. **7項（エクスポート）** — 列と絞り込みが固まってから。整形処理はマシン／セッション共通に作る。
7. **4項（メンテ絞り込み）** — UI設計の判断が必要。

## 設計上の注意

- 複数選択での一括操作は、**部分的失敗を正しく扱う**ことが要点。
  「全部成功」か「全部失敗」かの二択にせず、1件ずつの結果を集計して報告し、
  **どの対象が失敗したかを画面で確認できる**ようにする（2.1項）。
  この「対象ごとの結果」を持つ構造は、マシン・セッションの両方で共通に使う。
- 絞り込みは引き続き**クライアント側**で行う（DDC側フィルタは完全一致要求で使えない。
  [SPEC_phase4.md](SPEC_phase4.md) §7.1 の教訓）。
- 絞り込み条件が増えるほどUIが窮屈になる。**今回でツールバーは限界を超える**
  （マシン一覧: 更新／メンテON／OFF／Excelへコピー／CSV保存...／グループ／カタログ／種別／メンテ絞り込み／マシン名）。
  操作ボタン行とフィルタ行を**2段に分ける**前提で、レイアウトを先に決めてから
  個々の機能を載せること。機能ごとに後付けするとツールバーが破綻する。
- **マシン一覧とセッション一覧は同じ作りに揃える**。複数選択（2項・5項）、
  結果の内訳（2.1項）、エクスポート（7項）はいずれも両画面に入る。
  片方だけ実装して後から寄せるより、最初から共通部品として作る方が安い。
- 外部ライブラリを増やさない方針は維持する（7項の xlsx を見送る理由）。
  CSV・TSV・JSON はいずれも標準機能と既存の `JsonWriter` で書ける。
